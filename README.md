# DocMind — Local AI Document Intelligence

Offline AI chatbot that answers questions from your local document library using **Ollama llama3.2-vision**. Supports PDFs (with embedded images), Word docs, text files, and standalone images.

---

## Architecture

```
User Question
     │
     ▼
[ Next.js Frontend ]
     │  POST /api/v1/ask (streaming)
     ▼
[ FastAPI Backend ]
     │
     ├─► MemoryStore.search(query)      ← TF-IDF over in-memory chunks
     │       └─► Top-K relevant chunks (text + images)
     │
     ├─► QAService.stream_answer()
     │       ├─► Build context from chunks
     │       ├─► Attach relevant doc images (vision)
     │       └─► Stream via Ollama llama3.2-vision
     │
     └─► SSE stream back to frontend
```

## Setup & Run

### Prerequisites
- **Python 3.11+**
- **Node.js 18+**
- **Ollama** installed: https://ollama.ai

### 1. Pull the vision model
```bash
ollama pull llama3.2-vision
```

### 2. Backend setup
```bash
cd backend
python -m venv venv
source venv/bin/activate       # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Add documents
```bash
# Drop any PDFs, Word docs, text files, or images here:
cp your-files/* backend/knowledge_base/
```

### 4. Index documents (run offline, once)
```bash
cd backend
python -m services.indexer

# Options:
# --force       Reprocess all files from scratch
# --file doc.pdf  Process a single file
```
This uses llama3.2-vision to read and summarize every text chunk and image. Takes time — run before starting the API.

### 5. Start the API
```bash
cd backend
uvicorn main:app --reload --port 8000
```
On startup, all processed cache loads into RAM. Check: http://localhost:8000/health

### 6. Start the frontend
```bash
cd frontend
npm install
npm run dev
# Open http://localhost:3000
```

## Key Features

| Feature | Detail |
|---|---|
| **Vision-aware answers** | Images extracted from PDFs are passed to llama3.2-vision during answering |
| **In-memory retrieval** | All chunks loaded at startup — no database roundtrips |
| **Streaming responses** | Token-by-token SSE streaming to frontend |
| **Cancellation** | POST /cancel/{session_id} stops stream mid-response |
| **File attachment** | User can attach image or text file per question |
| **Dark / Light mode** | Persisted in localStorage, applied instantly |
| **Source attribution** | Each answer shows which documents + images were used |
| **Offline-first** | No cloud APIs, no telemetry — fully local |

## API Endpoints

| Method | Path | Description |
|---|---|---|
| GET | `/health` | Status + loaded chunk count |
| GET | `/api/v1/stats` | Document + chunk statistics |
| GET | `/api/v1/documents` | List all indexed documents |
| POST | `/api/v1/ask` | Stream answer (multipart/form-data) |
| POST | `/api/v1/cancel/{id}` | Cancel active stream |
| GET | `/api/v1/sources?q=...` | Preview which docs/images match a query |
| GET | `/api/v1/document/{id}/images` | All image URLs for a document |
| GET | `/images/{filename}` | Serve extracted document images |

## Re-indexing

When you add new documents:
```bash
cd backend
python -m services.indexer          # Only new/changed files
python -m services.indexer --force  # All files
```
Then restart the API to reload the cache.
